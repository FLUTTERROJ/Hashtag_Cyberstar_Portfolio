Support Atlas

Support Atlas is a web-based mental health support platform designed to make professional help more accessible.

  • Centralized hub for mental health services and trusted support pathways.
  • Chatbot-assisted guidance that routes users to relevant nearby services.
  • Location-aware discovery flow to reduce friction during help-seeking.

Support Atlas home interface with fast access to trusted support pathways.

Problem & Context

Why it mattered and constraints that shape the build.

Finding mental health support can be overwhelming, especially during moments of distress. Information about available services is often scattered across different platforms, making it difficult for users to quickly identify reliable and nearby support. Additionally, AI tools that attempt to provide direct mental health advice raise ethical and safety concerns.

This project aimed to create a centralized platform that simplifies access to mental health services. Instead of offering clinical advice, the chatbot guides users toward verified services and helps them find the nearest support options based on their location.

  • A central hub listing various mental health services (hotlines, counseling centers, clinics, crisis support)
  • A user-friendly, low-friction platform that simplifies help-seeking behavior
  • Designing a calm, reassuring interface suitable for sensitive contexts
  • A location-aware chatbot interface that helps users identify the nearest relevant service
  • Ensuring the chatbot does not provide clinical diagnosis or therapy

Solution Overview

Key features and the core workflow.

Structured and verified directory that consolidates mental health services — including hotlines, counseling centers, and clinics — into one accessible platform.
A conversational interface that helps users quickly identify relevant support options. The chatbot does not provide clinical advice, but instead directs users to appropriate services.
A discreet “Quick Leave” feature that allows users to instantly redirect the site if someone approaches them, particularly for users seeking help in sensitive environments.
An integrated map that detects the user’s location and displays the nearest mental health services, including distance, contact details, and directions.
Comprehensive accessibility modes including Easy Mode, Reduced Motion, Large Text Mode, Dyslexia-Friendly Mode, High Contrast and and Screen Reader Assist to ensure inclusivity
A clean, minimal interface designed to reduce cognitive overload, promote clarity, and create a safe digital environment for users seeking support.

Architecture

High-level system boundaries and tradeoffs.

Next.js App Router FastAPI Dango ORM Supabase
  • Fixed stack: Next.js App Router + TypeScript + FastAPI
  • DB + ORM: Django + Supabase for OAuth
  • Auth: GitHub OAuth + Goggle OAuth
  • Route handlers for explicit HTTP boundaries and consistent error schemas.

Failures & Challenges

What did not work first and what changed.

Route handlers were not wired correctly for one CRUD path.
Validation gaps created edge-case API failures in early testing.
Auth assumptions were too optimistic for cross-role access.
Pagination strategy needed refactor to stay fast under load.
